If you used Splox before, you built workflows: a canvas, nodes you dragged onto
it, edges between them, an entry node at the top. None of that exists now. The
product is an agent with its own Linux machine, and what the agent is, is Python
in a git repository.

This page is the map from the old vocabulary to the new one. Nothing here is a
rename — most of these are a different mechanism that does the same job.

## The vocabulary

| --- | --- | --- |
| Workflow | **Harness** — your agent's files, with a version history | [Harness](/concepts/harness) |
| The canvas | a **program**: a short piece of code the agent writes and edits for you | [Programs](/concepts/program) |
| Agent node | an **agent** declared in the harness: its prompt, its model, its tools | [Agents](/concepts/agent) |
| Entry node | the program that decides which agent answers a chat message | [Programs](/reference/programs) |
| Tool node | a **tool** the agent can call, kept with its files | [Tools](/reference/tools) |
| Switch node, conditional edge | an ordinary decision in the program | [Programs](/reference/programs) |
| Parallel edges | sub-agents run side by side | [Sub-agents](/reference/subagents) |
| Merge node | the program carrying on once those sub-agents finish | [Sub-agents](/reference/subagents) |
| Error edge | a **hook** that decides what happens when a model provider fails | [Hooks](/reference/hooks) |
| Tool edge | the agent's list of tools, and a hook that sees every call | [Hooks](/reference/hooks) |
| Variable mappings | what the program keeps, and what it tells a sub-agent | [Sub-agents](/reference/subagents) |

The old workflow, memory-instance and MCP-connection pages and the API behind
them are gone. The current API is [here](/api/introduction).

## Why the canvas went

**A graph draws the decisions in advance.** The model makes them per message,
with the whole conversation in front of it. Every branch that was drawn as a
switch node was a decision taken away from the model and frozen at design time.
What is left that a graph really did own — *which agent takes this message* — is
now a few lines in your program — for example, *messages that start with
/support go to the triage agent, everything else to the assistant* — because it
is the one thing only you can know.

**Code is reviewable and versioned.** A harness is a git repository. A version is
one saved state of it. A run records the exact version it ran, so you can read
back what produced any answer. A canvas had a version number; it did not have a
diff.

**Tools compose when they are called in code.** A tool called one at a time puts
its whole result back in front of the model, and the model pays for all of it. A
tool the agent calls from a short script can be chained with four others,
filtered, and made to print only the answer. That is why the agent here writes
small scripts rather than calling tools one by one.

**Hooks instead of forks.** The turn loop has named points — what the model sees,
which model runs, which tools it may use, what it remembers, what happens on an
error, when it stops — and a hook is a file that answers one of them. You change one decision without owning the loop, and a hook that fails
falls back rather than taking the run down.

## What has no replacement

There is no visual editor. If what you want is a fixed pipeline with phases and
checkpoints, you ask for it: the agent writes it as an ordinary program, with a
loop, a queue, retries and a database if it needs one. The starter carries a
worked example of that shape — the *compiler* program: several agents, phases,
picks up where it left off — and its README is the thing to read before building
anything similar.
