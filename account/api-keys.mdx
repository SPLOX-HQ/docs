title: "API keys"
description: "Getting a key for the API, what it can reach, how long it lives, and revoking it"

An API key is a token that stands for your whole account. It is what a program
of yours sends to Splox in place of your login, so it can do through the API
what you do in the app.

**Creating one requires a paid plan.** On a free account the request is refused
with *"Paid plan required to generate API tokens"*. Upgrade first; see
[Plans](/account/plans).

## Creating one

There is no key screen in the app: a key is created through the API itself,
signed in with your browser session, because it is the thing that gets you your
first key. [Getting a token](/api/authentication#getting-a-token) has the exact
call.

When you create a key you choose two things:

| | |
| --- | --- |
| **Name** | What the key is for, so you can recognise it later. If you leave it out, the key is named after the moment it was made. |
| **Lifetime** | How long it lives. One hour unless you say otherwise, and at most a year. There is no key that never expires. |

<Warning>
The key is shown once, at the moment it is created. Splox keeps only a
fingerprint of it, never the key itself. Copy it into an environment variable or
a secret store right away; if you lose it, create another.
</Warning>

Using it is one header on every call:

```text
Authorization: Bearer <your key>
```

The address to send it to is on [The API](/api/introduction).

## What it can reach

Everything your account can. **A key is the account, not a subset of it** —
there is no way to narrow it to one part. It starts runs that spend your
allowance, reads every run your account owns, and can create and revoke further
keys. Treat it accordingly: a short life for anything short-lived, a separate
key for each thing that holds one, and revoke rather than share.

What it is **not**:

- Not a provider key. Your OpenAI or Anthropic credentials live under
  **Connections** and are a separate thing entirely — see [Model](/concepts/model).
- Not a login to a machine. The agent's own tools run inside the machine and
  need no key from you.
- Not limited to one agent, one machine or one run.

## Seeing your keys

The list of your keys shows each one's name, when it was made and when it
expires — never the key itself. Expired keys drop off the list rather than
staying as dead rows, so everything you see there is live.

## Revoking

Revoking a key takes effect at once — the next request made with it is refused,
with nothing to wait out. A key you no longer recognise is a key to revoke;
there is no cost to creating a fresh one.

Letting a key expire has the same end state. If you know a key is for one job,
give it a lifetime that covers the job and nothing more, and you never have to
remember to come back.
