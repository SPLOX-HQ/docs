---
title: "When a limit is reached"
description: "What a full usage window does to a request, to a chat and to a run in progress — and what does not lift it"
---

A full window is not a broken account and not an empty one. It means you are
going faster than your plan allows, and the useful facts are which window ran
out, how full it is, and the moment it frees up. Every place below tells you
all three.

## First: a full window is not always a refusal

Who pays is decided once for each piece of work, in this order:

1. **The plan pays** while neither window is full.
2. **The wallet pays** when a window is full and there is money in it — at list
   prices, as [extra usage](/account/extra-usage).
3. **Nothing pays**, and the request is refused.

So a window at 100% only refuses you when there is nothing behind it. On a free
account there is nothing behind it by definition: the wallet cannot be filled
without a paid plan. On Pro or Max with a funded wallet, a full window changes
what you are charged, not whether you are served.

## Which wait you are told

When both windows are full, the wait you are quoted is the **later** of the two
resets, not the earlier: clearing the 5-hour window while the weekly one is
still full would only get you a second refusal, so the time you are given is
the one that actually ends it. Waiting exactly that long is enough.

## In the app

A refused request raises one warning, titled with the window that refused
(**5-hour limit reached**) and reading *"You are going faster than your plan
allows. Resets 12:19 PM UTC · in 4h 5m"*. No pop-up, no checkout button: you
have not run out of money, and offering a payment page would be both wrong and
expensive. The usage screen refreshes behind it so the bars agree with what you
were just told.

Several requests refused at once still produce one warning.

## In a chat

If the window fills before a turn starts, the turn does not start and the
warning is all there is. If it fills **while the agent is working**, the run
stops where it is and the assistant's last message is the reason, in plain
words:

> You have used your 5-hour limit. It frees up at 12:19 UTC on 2 Sep 2026.

Everything the run had already done stays: the messages, the tool calls, the
files it wrote on the machine. Nothing is rolled back. Send the message again
after the reset and the agent picks up from a machine that still has its work on
it.

A full window and an empty wallet are deliberately told apart: one is fixed by
waiting and the other by paying, and sending somebody with money in their
account to a checkout helps nobody. Only the empty wallet opens the top-up
dialog — see [Extra usage](/account/extra-usage#running-low).

## What lifts it

| | |
| --- | --- |
| **Waiting for the reset** | The whole window comes back at that moment, not gradually. |
| **Moving up a plan** | Raises the cap now. What you have spent stays spent; it is measured against the new plan's cap, so a window that read 100% reads a fraction of that as soon as the subscription is active. |
| **Money in the wallet** (paid plans) | Does not raise the cap. It pays for work past the full window at list prices — that is extra usage. |

## What does not

- **Retrying sooner.** The window has not moved; you get the same refusal.
- **A new chat, a new machine, a second agent.** The windows belong to the
  account. Nothing about where the work runs changes them.
- **Topping up, on a free account.** The wallet needs a paid plan before it can
  hold anything, so on Free the only two answers are waiting and upgrading.
- **Canceling and resubscribing.** The window records what the account spent,
  not what the subscription did. A new subscription changes the cap; it does not
  erase the spend inside an open window.

## Refusals that look alike

| What you see | What it is | What fixes it |
| --- | --- | --- |
| **5-hour limit reached** / **Weekly limit reached** | a plan window is full, with nothing behind it | waiting, or a bigger plan |
| A request to slow down | too many requests at the same moment | wait a moment and try again |
| *"your plan runs one machine at a time"* | more machines than the plan runs | delete one, or a bigger plan |
| *"Your balance is below $0.50. Top up to continue."* | the wallet is under $0.50 with the windows full | topping up |

The second one is about how many requests arrive at once and has nothing to do
with your allowance.
